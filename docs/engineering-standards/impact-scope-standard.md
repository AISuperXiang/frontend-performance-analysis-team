# 性能方案上下文影响范围标准

## 代码与架构范围

- 列出直接修改候选文件、模块、组件、路由、共享库、构建配置和外部依赖。
- 区分局部影响、共享影响、跨应用影响和基础设施影响。
- 记录接口、数据流、SSR/CSR 边界和缓存契约变化。

## 运行时与用户范围

- 列出受影响旅程、设备、网络、浏览器、地域、用户群和访问频率。
- 映射预期改善与可能退化的指标、阶段和资源。
- 说明冷启动、暖缓存、首次交互、长会话和异常路径差异。

## 质量与发布范围

- 列出功能回归、视觉、可访问性、SEO、数据一致性、监控和测试范围。
- 说明灰度、回滚、缓存失效、兼容性和观测窗口。
- 不可回滚或跨团队变更必须升级为用户决策。

## 边界与责任

- 每个影响项指定确认角色或后续实施团队。
- 未知影响不能留空，必须标记 unknown 并给确认动作。
- 实施交接明确本团队不修改代码，由 ai-work-team 重新核对当前代码后执行。
