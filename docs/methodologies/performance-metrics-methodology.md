# 前端性能指标与预算方法论

## 核心体验指标

- LCP、INP、CLS 用于描述加载、交互和视觉稳定性，阈值必须记录标准来源和适用时间。
- 指标必须绑定页面、路由、旅程、设备、网络、版本和统计窗口。
- 单个核心指标不能替代用户旅程和业务结果。

## 诊断指标

- 按场景补充 TTFB、FCP、TBT、Long Tasks、LoAF、资源时序、CPU、内存、帧率和自定义 User Timing。
- 诊断指标用于解释机制，不能与现场体验指标混为同一口径。
- 每个指标必须说明单位、采集 API、支持范围和已知偏差。

## 分位数与分群

- 现场分析默认至少观察 p50、p75、p95 和样本量，按设备、网络、地域、浏览器、版本和路由分群。
- 实验室重复采样默认报告中位数、范围和异常值，不能只给平均值。
- 样本不足、采样偏差或分群过细时降低结论等级。

## 性能预算

- 预算应覆盖用户体验指标、关键资源、主线程工作、第三方和关键旅程。
- 预算必须区分当前基线、目标、守门阈值和告警阈值。
- 预算变化需要说明业务价值、设备覆盖、监控来源和复盘周期。
