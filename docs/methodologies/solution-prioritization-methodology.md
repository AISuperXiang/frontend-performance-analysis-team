# 性能优化方案决策与落地方法论

## 候选方案

- 至少比较保持现状、局部优化和结构性优化，说明每项方案解决的根因和不解决的问题。
- 证据不足的根因先转成验证任务，不把补证与正式优化混在同一承诺中。
- 方案必须符合项目现有框架、构建、监控和发布约束，偏离时说明必要性。

## 优先级模型

- 综合用户影响、指标影响、根因置信度、实现成本、回归风险、依赖、可逆性和学习价值排序。
- 高影响低置信方案先做验证切片，高置信低风险方案可进入 quick wins。
- 分数只辅助排序，关键架构取舍必须写入决策日志。

## 影响与权衡

- 每个方案覆盖代码、路由、运行时、用户群、指标、依赖、测试、发布、监控和回滚影响。
- 说明功能正确性、可访问性、SEO、缓存一致性、开发体验和维护成本副作用。
- 预期收益使用范围或假设，并绑定前后对比协议和失效条件。

## 落地节奏

- Phase 0 固化基线与观测，Phase 1 处理可逆高置信项，Phase 2 处理结构性瓶颈，Phase 3 灰度、现场验证和复盘。
- 每个阶段都有输入、任务边界、责任团队、验证指标、回归范围、停止和回滚条件。
- 本团队只交付路线图；代码实现、测试和发布由用户批准后的 ai-work-team 承接。
