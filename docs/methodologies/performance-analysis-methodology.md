# 证据驱动的前端性能分析方法论

## 问题建模与基线

- 先把慢、卡、白屏或掉帧转成明确的用户、旅程、版本、环境、指标和阈值。
- 基线必须记录代码版本、URL、浏览器、设备、网络、CPU、缓存、数据状态和采样时间。
- 没有可比较基线时，先交付测量计划，不直接进入优化方案。

## 三角证据

- 静态证据回答代码和构建可能做了什么，浏览器证据回答运行时实际发生了什么，现场证据回答真实用户受影响多少。
- 完整评估至少需要静态与浏览器两类证据；现场数据缺失时必须标记为实验室结论。
- 三类证据冲突时保留冲突并设计补证，不用平均、投票或经验覆盖。

## 因果归因

- 每个问题使用指标或现象、原始证据、触发条件、代码或资源位置、机制解释、替代解释和置信度链路。
- 综合评分、相关性和代码气味只能产生假设，不能单独完成根因归因。
- 优先使用受控对照、版本差异、局部禁用或可重复 trace 验证因果。

## 结论等级

- V1 只允许静态风险结论，V2 允许可重复脚本或受控模拟结论，V3 需要真实浏览器关键路径，V4 需要现场或灰度收益证据。
- 最终报告为每个主要结论标记验证等级、置信度、未覆盖范围和失效条件。
- 团队生成时的工厂 V2 不得用于抬高具体性能任务的业务验证等级。
