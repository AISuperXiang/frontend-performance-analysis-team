# 前端性能静态分析方法论

## 应用与构建建模

- 识别框架、渲染模式、入口、路由、构建工具、产物形式、部署方式和共享依赖。
- 记录 package、lockfile、构建配置与目标代码版本的一致性。
- 无法确认生产构建方式时，静态结论必须注明环境假设。

## 关键路径扫描

- 沿关键旅程追踪入口、chunk、数据请求、组件、样式、图片、字体和第三方资源。
- 检查同步加载、动态加载、tree-shaking、重复依赖、polyfill、source map 和资源优先级。
- 将总资源成本与关键路径成本分开，避免仅按文件大小排序。

## 运行时风险信号

- 检查同步重计算、过度渲染、布局读写交错、全局监听、未清理定时器、大对象持有和主线程密集任务。
- SSR 应检查数据串行、流式边界、Hydration 范围、一致性和客户端重复请求。
- 所有静态信号都必须转成可由浏览器或测试验证的假设。

## 源码到证据映射

- 发现必须记录文件、符号或配置位置、关联旅程、可能指标和影响机制。
- source map 或 trace 可用时，将任务和网络资源映射回源文件与依赖。
- 共享基础模块、公共组件和局部页面必须分别标记影响半径。
