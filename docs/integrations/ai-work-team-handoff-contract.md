# ai-work-team 实施交接契约

## 交接触发

- 只有用户明确批准进入实施后，才建议调用 ai-work-team。
- 分析报告、推荐方案、影响范围和路线图未通过门禁时不得交接为已定方案。
- 实现紧急程度不能跳过代码现状复核和测试计划。

## 必需上下文

- 交接包含目标旅程、基线、根因证据、推荐方案、未选方案理由和成功指标。
- 必须包含候选代码范围、依赖、回归面、发布、监控、回滚和停止条件。
- 每个实施切片说明优先级、预期收益、验证方式、风险和责任角色。

## 执行边界

- ai-work-team 必须重新读取当前代码和项目约定，不能假设分析时版本未变化。
- 实现范围不得扩展到报告未覆盖的重构，新增范围必须回到决策记录。
- 本性能团队不对未执行代码或未运行测试声明完成。

## 回传与复盘

- 实施完成后回传实际改动、测试、浏览器复测、现场指标和偏差。
- 收益低于预期时重新检查根因、实施偏差、环境和指标口径。
- 复盘结果更新方案假设、性能预算和后续路线图。
